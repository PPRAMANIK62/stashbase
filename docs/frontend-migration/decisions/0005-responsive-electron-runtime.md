# Make responsiveness an architectural acceptance constraint

The replacement renders a minimum safe shell before independently settling
noncritical capabilities, keeps native orchestration in Electron main,
interaction on the renderer thread, expensive view work in Web Workers, and
filesystem or durable work in the server and sidecars. Loading preserves safe
content and local interaction, while optimistic updates are limited to
reversible low-risk metadata. Reproducible CI budgets cover bundle size,
startup stages, key interactions, long tasks, and memory after disposal. This
accepts explicit scheduling, cancellation, streaming, and measurement work to
make responsiveness and good recovery enforceable rather than subjective.
